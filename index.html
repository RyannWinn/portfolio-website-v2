FitFindr

◆ AI201 Applications of AI Engineering

FitFindr is a shopping agent for creating outfits and finding the top secondhand listings based off your preference. You describe what you want. For example, it can be "I'm looking for a vintage graphic tee under $30 that works with baggy jeans." It searches listings and then styles the piece against the wardrobe you already own.

  • Includes a three-step agent loop: searches listings, builds an outfit from the user's wardrobe, then writes a shareable fit card.
  • Wardrobe is stored against a JSON schema so suggestions reference real items, with an empty-wardrobe path for new users.
  • Every step includes guardrails. A non-empty outfit suggestion is required before the fit card is generated and failures return a readable error instead of a hallucination.
  • Filters on size and price so that the results stay inside of what the user asked for.
  • Anything over budget or in the wrong size gets filtered out, scores the rest by keyword overlap with the description, drops zero-score items, and returns the matches ranked best-first.

B2

The Unofficial Guide

◆ AI201 Applications of AI Engineering

The Unofficial Guide answers questions about college professors from real RateMyProfessors student reviews. Every response lists the exact review chunks behind it so you can check the source instead of just trusting the model. There is an option to restrict to only certain professors for tailored results.

  • A clean interface with Gradio where users can type a question, read the answer, and inspect the exact reviews used.
  • End-to-end retrieval pipeline: ingestion, cleaning, and chunking 10 RateMyProfessors sources into 47 embedded chunks in a ChromaDB vector store using a recursive 230-token window with 20-token overlap.
  • Embeddings via all-MiniLM-L6-v2, with a top-k slider so you can widen or tighten retrieval per question.
  • Off-topic questions are refused before any LLM call and it can't invent an answer it has no sources for.
  • Respones from the LLM cite documents inline and can be scoped to a single professor.

University Course Management System

CSE2050 Data Structures & Algorithms

A full course-registration system that tracks student academic records, course catalogs, prerequisite requirements, and waitlists through a University.

  • Adds students into class, check class capacities to prevent overfilling, and enforces prerequisites. Records letter grades and automatically computes GPAs based on course credits.
  • Hash mapping with separate chaining and dynamic rehashing to hold lookups at O(1) as the catalog grows.
  • Recursive binary search for retrieval. Created a merge sort and quick sort for roster ordering at time complexity of O(n log n).
  • Enrollment validates prerequisites before registering a student and routes over-capacity courses through a custom linked queue.
  • Reads CSV files containing student rosters, course catalogs, and prerequisite trees to simulate an actual university database.
